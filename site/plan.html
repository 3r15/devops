대상과 전제

대상터미널을 열어본 적은 있지만 서버를 혼자 운영해본 적은 없는 사람
전제 지식없음. 파일과 폴더 개념, 그리고 영어 문서를 읽을 인내심 정도
필요 환경리눅스를 돌릴 수 있는 무언가 — VM, WSL2, 클라우드 프리티어 인스턴스 중 하나
끝났을 때작은 웹 서비스를 컨테이너로 만들고, 파이프라인으로 배포하고, 메트릭과 로그로 상태를 보고, 장애가 났을 때 어디부터 볼지 아는 상태

학습 원칙

1. 손이 먼저다

개념 설명은 명령어를 이해하기 위한 최소한만 둔다. 각 단계의 절반 이상은 실습이다.

2. 한 단계 = 하나의 산출물

읽은 것으로는 끝나지 않는다. 스크립트든 매니페스트든 남는 물건으로 끝낸다.

3. 앞 단계 위에 쌓는다

Stage 7의 컨테이너는 Stage 6에서 세운 웹 서버를 담는다. 예제는 하나의 서비스를 계속 키운다.

4. 틀리는 법도 배운다

각 단계에 '자주 하는 실수'를 둔다. 에러 메시지를 먼저 보여주고 읽는 법을 가르친다.

5. 검증 가능한 완료 기준

'이해했다'가 아니라 '이 명령이 이 출력을 내면 통과'로 적는다.

관통 예제 — weatherboard

전 단계를 관통하는 하나의 예제 서비스를 둔다. 날씨 API를 조회해 페이지를 그려주는 아주 작은 HTTP 서비스를 Stage 5에서 만들고, 이후 단계에서 계속 감싼다. 도구를 따로따로 배우는 대신 하나의 서비스가 자라는 과정으로 배우기 위한 장치다.

건너뛰기 지침

건너뛰어도 되는 경우

이미 개발자라 Git과 Python을 쓴다면 Stage 3과 5는 체크리스트만 통과하고 넘어가도 된다. 목표가 특정 직무(예: 쿠버네티스 운영)라면 Stage 1·2·7·8·13을 먼저 하고 나머지를 나중에 해도 된다.

건너뛰면 안 되는 것

Stage 1(Linux)과 Stage 2(Networking). 이후 모든 장애 대응이 이 둘에서 갈린다. 도구는 바뀌어도 이 둘은 바뀌지 않는다.
