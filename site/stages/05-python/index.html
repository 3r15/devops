1. 가상환경과 의존성

프로젝트마다 필요한 패키지와 버전이 다르다. 가상환경은 프로젝트별로 격리된 파이썬 설치본을 만들어 그 충돌을 없앤다.

mkdir weatherboard && cd weatherboard
python3 -m venv .venv
source .venv/bin/activate        # 프롬프트 앞에 (.venv)가 붙는다
which python                     # /path/to/weatherboard/.venv/bin/python

pip install requests
pip freeze > requirements.txt    # 지금 설치된 것을 버전까지 고정
deactivate                       # 빠져나오기

다른 사람(또는 미래의 나, 또는 Stage 7의 Docker)이 같은 환경을 재현하는 방법은 이것이다.

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

.venv/는 커밋하지 않는다. Stage 3에서 만든 .gitignore에 넣는다.

printf '.venv/\n__pycache__/\n*.pyc\n.env\n' >> .gitignore

💡 requirements.txt를 나누는 관례

실행에 필요한 것과 개발에만 필요한 것(pytest 등)을 나누면 배포 이미지가 작아진다. requirements.txt와 requirements-dev.txt로 나누는 방식이 가장 단순하고, Stage 7에서 이미지를 만들 때 실제로 도움이 된다.

셸에서 문자열과 배열만으로 애를 먹던 일들이 여기서 쉬워진다.

# 셋 — 중복 없는 모음

⚠ 들여쓰기가 문법이다

파이썬은 중괄호 대신 들여쓰기로 블록을 구분한다. 스페이스 4칸이 관례이고, 탭과 스페이스를 섞으면 TabError가 난다. 편집기에서 "탭을 스페이스로" 설정을 켜 두면 이 문제를 영원히 겪지 않는다.

3. 파일과 경로

from pathlib import Path

log = Path("/var/log/syslog")
print(log.exists(), log.name, log.suffix, log.parent)

# 읽기 — with를 쓰면 블록을 벗어날 때 자동으로 닫힌다
with open("config.txt", encoding="utf-8") as f:
    for line in f:
        line = line.strip()
        if not line or line.startswith("#"):
            continue
        print(line)

# 쓰기
Path("report.txt").write_text("생성 완료\n", encoding="utf-8")

# 디렉터리 순회
for p in Path("/var/log").glob("*.log"):
    print(p, p.stat().st_size)

encoding="utf-8"을 항상 명시하자. 기본 인코딩은 환경에 따라 달라서, 내 노트북에서는 되고 서버에서는 UnicodeDecodeError가 나는 원인이 된다.

JSON과 YAML

import json

data = json.loads('{"host": "web01", "cpu": 87.5}')    # 문자열 → 파이썬
print(data["cpu"])

Path("state.json").write_text(text, encoding="utf-8")

with open("state.json", encoding="utf-8") as f:
    data = json.load(f)                                 # 파일에서 바로

셸에서 jq로 힘겹게 하던 일이 두 줄이다. JSON을 다뤄야 한다면 셸을 떠날 때라는 Stage 4의 신호가 이것이다. YAML은 표준 라이브러리에 없어 pip install pyyaml이 필요하고, yaml.safe_load()를 쓴다(load()는 임의 코드 실행 위험이 있다).

4. 예외 — 실패를 다루는 법

셸에서 ||와 종료 코드로 하던 일을 파이썬은 예외로 한다. 훨씬 정밀하다.

try:
    with open("config.json", encoding="utf-8") as f:
        config = json.load(f)
except FileNotFoundError:
    config = {}                       # 없으면 기본값으로
except json.JSONDecodeError as e:
    raise SystemExit(f"config.json 형식이 잘못됐다: {e}")
finally:
    print("여기는 무슨 일이 있어도 실행된다")

⚠ except: 만 쓰지 않는다

맨 except:나 except Exception:은 모든 예외를 삼킨다. 오타로 인한 NameError까지 숨겨서, 코드가 조용히 잘못된 답을 내게 만든다. 잡을 예외를 구체적으로 적자. 정말 모두 잡아야 한다면 최소한 로그는 남긴다.

except Exception:
    logging.exception("예상치 못한 오류")   # 스택 트레이스까지 기록
    raise                                    # 다시 던진다

로깅

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
)
log = logging.getLogger(__name__)

log.info("시작")
log.warning("디스크 사용률 %d%%", 91)     # % 포맷 인자를 넘긴다 (문자열을 미리 만들지 않음)
log.error("API 호출 실패")

print 대신 logging을 쓰면 레벨로 걸러내고, 형식을 바꾸고, 파일이나 저널로 보낼 수 있다. Stage 13(모니터링)에서 이 로그가 수집 대상이 된다. 기본 출력은 stderr이라, Stage 4에서 정한 "결과는 stdout, 말은 stderr" 규칙과도 맞는다.

5. 셸 명령 실행하기

import subprocess

result = subprocess.run(
    ["df", "-h", "--output=pcent", "/"],
    capture_output=True,
    text=True,
    check=True,        # 0이 아닌 종료 코드면 예외
    timeout=10,        # 매달리지 않게
)
print(result.stdout)

인자를 리스트로 넘기는 것이 핵심이다. 문자열과 shell=True를 쓰면 셸이 한 번 더 해석해서, 입력에 ;나 $()가 들어오면 임의 명령이 실행된다.

# 위험 — 사용자 입력이 들어오면 명령 주입
subprocess.run(f"ping -c1 {host}", shell=True)

# 안전 — 리스트는 셸을 거치지 않는다
subprocess.run(["ping", "-c1", host], check=True)

💡 그런데 정말 셸을 불러야 하나

파일 목록이 필요하면 ls를 부르지 말고 Path.glob()을, 디스크 정보는 shutil.disk_usage()를 쓰자. 외부 명령은 없을 수도, 버전이 다를 수도, 출력 형식이 바뀔 수도 있다. 표준 라이브러리로 되는 일은 표준 라이브러리로 한다.

import shutil
total, used, free = shutil.disk_usage("/")
print(f"{used / total * 100:.1f}% 사용 중")

⚠ timeout을 빼먹지 않는다

requests는 기본 타임아웃이 없다. 상대 서버가 응답하지 않으면 내 프로그램이 영원히 멈춘다. cron이나 타이머로 도는 스크립트라면 이런 프로세스가 계속 쌓인다. 모든 네트워크 호출에 timeout을 준다 — 예외 없이.

Stage 2에서 배운 것이 여기서 코드가 된다. 어떤 실패가 어떤 예외로 오는지 보자.

try:
    resp = requests.get(url, timeout=5)
    resp.raise_for_status()
except requests.Timeout:
    log.error("응답 없음 — 방화벽이나 느린 백엔드")        # Stage 2의 timed out
except requests.ConnectionError:
    log.error("연결 실패 — DNS 또는 포트")                  # refused / 이름 해석 실패
except requests.HTTPError as e:
    log.error("HTTP %s", e.response.status_code)           # 4xx/5xx

비밀은 코드에 넣지 않는다

import os

api_key = os.environ.get("WEATHER_API_KEY")

argparse는 --help를 자동으로 만들고, 타입 변환과 검증까지 해 준다. Stage 4에서 case로 손수 짜던 파싱이 여기서는 선언 몇 줄이다.

# weatherboard/weather.py
import logging
import requests

log = logging.getLogger(__name__)
API = "https://api.open-meteo.com/v1/forecast"


def fetch_current(lat: float, lon: float, timeout: float = 5.0) -> dict | None:
    """현재 날씨를 가져온다. 실패하면 None을 돌려준다."""
    try:
        resp = requests.get(
            API,
            params={"latitude": lat, "longitude": lon,
                    "current": "temperature_2m,wind_speed_10m"},
            timeout=timeout,
        )
        resp.raise_for_status()
    except requests.RequestException:
        log.exception("날씨 조회 실패 lat=%s lon=%s", lat, lon)
        return None

    return resp.json().get("current")


def format_line(city: str, temp_c: float) -> str:
    return f"{city}: {temp_c:.1f}°C"
# weatherboard/app.py
import http.server
import json
import logging
import os

from .weather import fetch_current, format_line

CITIES = {"서울": (37.57, 126.98), "부산": (35.18, 129.08)}
log = logging.getLogger(__name__)


class Handler(http.server.BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/healthz":          # Stage 8의 프로브가 이 경로를 쓴다
            self._send(200, "text/plain", "ok")
            return

        lines = []
        for city, (lat, lon) in CITIES.items():
            current = fetch_current(lat, lon)
            if current is None:
                lines.append(f"{city}: 조회 실패")
            else:
                lines.append(format_line(city, current["temperature_2m"]))

        self._send(200, "text/plain; charset=utf-8", "\n".join(lines))

    def _send(self, code: int, ctype: str, body: str):
        data = body.encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", ctype)
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

    def log_message(self, fmt, *args):       # 기본 로그를 logging으로 보낸다
        log.info("%s - %s", self.address_string(), fmt % args)


def main() -> int:
    logging.basicConfig(level=logging.INFO,
                        format="%(asctime)s %(levelname)s %(message)s")
    port = int(os.environ.get("PORT", "8000"))
    host = os.environ.get("HOST", "127.0.0.1")
    log.info("listening on %s:%s", host, port)
    http.server.HTTPServer((host, port), Handler).serve_forever()
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

💡 두 가지가 의도적으로 심어져 있다

/healthz는 Stage 8에서 쿠버네티스 프로브가 부를 경로이고, HOST/PORT를 환경변수로 받는 것은 Stage 7에서 컨테이너가 설정을 주입할 방법이다. 기본 HOST가 127.0.0.1인 것도 의도적이다 — Stage 2에서 본 대로 밖에서 붙지 않는다. 컨테이너에서는 0.0.0.0으로 바꿔 띄운다.

⚠ http.server는 실서비스용이 아니다

표준 라이브러리의 http.server는 요청을 하나씩 처리하고 보안 검토도 되어 있지 않다. "배우기 위한 최소 구현"으로만 쓴다. 실제 서비스라면 Flask/FastAPI 같은 프레임워크와 gunicorn/uvicorn 같은 WSGI/ASGI 서버를 쓰고, 그 앞에 Nginx를 둔다 — 그게 Stage 6이다.

자주 하는 실수

error: externally-managed-environment

pip install requests
# error: externally-managed-environment
# × This environment is externally managed

배포판이 관리하는 시스템 파이썬을 보호하는 장치다. --break-system-packages로 뚫으라는 조언이 인터넷에 많지만, 이름 그대로 시스템을 깨뜨릴 수 있다. 정답은 가상환경을 만드는 것이다.

python3 -m venv .venv && source .venv/bin/activate && pip install requests

ModuleNotFoundError: No module named 'requests'

설치는 했는데 못 찾는다면, 설치한 파이썬과 실행하는 파이썬이 다른 것이다. 가상환경을 activate하지 않았거나, sudo python으로 실행했거나, 다른 터미널을 쓰고 있다.

which python pip          # 둘 다 .venv 안을 가리켜야 한다
python -m pip install requests    # 지금 이 파이썬에 설치 (가장 확실한 방법)

IndentationError / TabError

  File "app.py", line 12
    return data
    ^
IndentationError: unindent does not match any outer indentation level

탭과 스페이스가 섞였거나 들여쓰기 깊이가 어긋난 것이다. 편집기에서 공백 문자를 보이게 켜고, 파이썬 파일은 스페이스 4칸으로 통일한다.

UnicodeDecodeError

with open("log.txt") as f:     # 인코딩 미지정
# UnicodeDecodeError: 'ascii' codec can't decode byte 0xed ...

기본 인코딩은 로케일에 따라 달라진다. 서버의 LANG이 C면 ASCII로 읽으려다 한글에서 터진다. encoding="utf-8"을 항상 명시하고, 깨진 바이트를 무시해야 한다면 errors="replace"를 쓴다.

스크립트가 영원히 멈춰 있다

requests.get()에 timeout을 안 준 것이다. 상대가 응답하지 않으면 무한정 기다린다. cron이나 타이머로 도는 스크립트라면 이런 프로세스가 계속 쌓여 결국 메모리를 다 쓴다. subprocess.run()도 마찬가지로 timeout=을 준다.

직접 해보기

과제 1 — weatherboard v0 만들기

위 구조대로 저장소를 만들고 동작시킨다. README.md에는 클론한 사람이 그대로 따라 하면 실행되는 명령만 적는다.

검증: 저장소를 다른 디렉터리에 새로 클론해서, README만 보고 curl localhost:8000이 응답할 때까지 갈 수 있는가. 빠진 단계가 있다면 README를 고친다.

과제 2 — 실패를 만들고 처리 확인하기

API 주소를 존재하지 않는 도메인으로 바꿔 보고, 방화벽으로 막아 보고(Stage 2 과제 3의 방법), 타임아웃을 0.001초로 줄여 본다. 각각 어떤 예외가 오는지 확인하고, 세 경우 모두 서비스가 죽지 않고 "조회 실패"를 응답하는지 본다.

검증: 세 경우 모두 curl localhost:8000이 500이 아니라 200과 함께 "조회 실패" 문구를 돌려주는가. 로그에 원인이 남는가.

과제 3 — 테스트 붙이기

format_line의 반올림, fetch_current의 타임아웃 처리, 잘못된 좌표 입력 세 가지에 대한 테스트를 쓴다. 외부 호출은 monkeypatch로 끊는다.

검증: pytest -q가 전부 통과하고, 네트워크를 끊은 상태에서도 통과하는가. (네트워크가 필요하다면 테스트가 잘못 짜인 것이다.)

과제 4 — 셸 스크립트를 파이썬으로 옮기기

Stage 4의 sysreport.sh를 sysreport.py로 다시 쓴다. 단, subprocess로 df를 부르지 말고 shutil.disk_usage()를 쓰고, 출력은 --json 옵션으로 JSON을 낼 수 있게 한다.

검증: python sysreport.py --json | python -m json.tool이 에러 없이 파싱되는가. 임계값 초과 시 종료 코드가 1인가. 셸 버전과 파이썬 버전 중 어느 쪽이 읽기 쉬운지 스스로 판단해 보자 — 정답은 경우에 따라 다르다.
